# SiloForge v2 security audit

Date: 2026-10-13. Scope: `crates/**` (static review), the axum route table (`sf-server/src/v1/mod.rs`, `v2/mod.rs`), the MCP transport, backups and the dependency tree. The source was only read, never edited (`sf-engine`/`sf-jobs` were being changed by another agent while this audit ran, so re-check line numbers in those crates). The one PoC lives outside the repo, in `D:\tmp\sf-sec\poc-llm\`, and was run against the current tree.

Paths are relative to `crates/` unless noted. Severity: **C** critical, **H** high, **M** medium, **L** low, **I** informational.

**Totals: C 0 · H 2 · M 4 · L 17 · I 5.**

**Resolution (2.0.2):** every Low/Info item is now fixed or carries a written justification (only L-12's localStorage part, L-13, L-15's blob binding and L-16 stay as justified residuals); see the Resolution column and the v1/integration tables.

**Resolution (2026-10-14, security-fix pass):** H-02, M-01..M-04, L-01, L-03, L-08, L-12, I-01, I-03, I-04 fixed with regression tests; L-05, L-10, L-14, L-16 partly fixed; H-01 fixed separately (engine agent); the rest accepted as documented in the Resolution column. Commit-ready: `cargo clippy -D warnings` and `cargo test` green for sf-crawl, sf-store, sf-ops, sf-server, sf-jobs, siloforge.

### Verified correct (evidence)
- **Ownership (IDOR):**
  - Every site-scoped v1 route calls `guard_user_site`/`guard_site` first (`v1/common.rs:187-205`). Child IDs are resolved to their site and then gated: edges (`v1/edges.rs:113-114,184-185`), keyword and ignore rules (`v1/rules.rs:151,189,279` via `owner_of`), schedules (`v1/schedules.rs` delete), jobs (`v1/jobs.rs:42-70`, `v2/jobs.rs:93-113`).
  - `bulk_decide` is scoped in SQL (`v1/edges.rs:257-261`). Inject and undo payloads are re-filtered by `site_id` in the pipelines (`sf-jobs/src/pipelines/inject.rs:208`, `undo.rs:109`). `run_now` looks up schedules with `site_id` (`v1/schedules.rs`). Foreign IDs answer 404.
  - Tokens: list and revoke are owner-scoped unless admin (`v2/tokens.rs:38,177`). Backups, notifications, errors, audit and system are `Admin`.
- **Site-token reach:** only the four plugin handlers take `Auth` (`v1/sync.rs:52,174,244,321`). Everything else needs `User`, which rejects site tokens (`auth.rs:277-295`), and site tokens are pinned to their own site (`auth.rs:320-326`).
- **API-token scopes:** method-based (`read` allows GET/HEAD/OPTIONS only, `auth.rs:249-263`). Admin routes require the `admin` or `*` scope plus the admin role (`auth.rs:297-309`). Tokens cannot change passwords (`v1/auth.rs:222-226`). No GET handler with side effects was found (`last_used_at` only).
- **JWT:** HS256 pinned and `exp` required (`sf-core/src/crypto.rs:47-58`). Users are re-checked for existence, role and `token_version` on each request, with a 30 s cache cleared on change-password, revoke and rotate (`auth.rs:210-240`).
- **Timing:** login always runs one bcrypt compare (`v1/auth.rs:167-173`). Handshake uses a constant-time compare (`v1/auth.rs:305-309`). Token lookup is by SHA-256.
- **SSRF:** the guard runs on every redirect hop (`sf-crawl/src/client.rs:377,423`) and the resolved IPs are pinned via `GuardedResolver` (`client.rs:382`, `ssrf.rs:321-333`, so no DNS-rebind window). Mapped, compatible, NAT64, 6to4, ULA, link-local and CGNAT ranges are blocked (`ssrf.rs:186-222`). Basic auth is dropped cross-origin (`client.rs:461-463`). `allow_private_hosts=false` by default.
- **Crypto:** stored secrets use a random 96-bit nonce (`crypto.rs:119-120`). The backup STREAM construction puts the header in the AAD, and a chunk counter plus a last-chunk flag in the nonce, so reordering, truncation and appending are detected (`sf-ops/src/backup/crypt.rs:49-55,77-80,106-113,164-179`). Backups use scrypt with a random salt.
- **Secrets in output:**
  - WP credentials live in `secrets_enc`, and legacy plaintext is stripped on read and on write (`v1/common.rs:350-372,393-430`). GSC credentials are sealed (`v1/gsc.rs`).
  - Provider keys are masked (`v1/providers.rs:104-120`). Notification channel secrets are encrypted and masked.
  - `/system` skips secret config fields. Audit rows log only key names or booleans. MCP output goes through `strip_secrets` plus `sf_`/`sfk_` value redaction (`sf-mcp/src/output.rs`, `client.rs:300-317`).
- **Injection:**
  - No SQL is built from user input; all `format!` SQL uses constant identifiers, and LIKE is escaped (`v1/posts.rs:68-79,113`). Content-Disposition uses `safe_filename_part` plus domain character filtering.
  - Link hrefs are limited to http(s) or a site-relative path and are attribute-escaped (`sf-engine/src/insert/splice.rs:47,416`). `/sync`, CSV import, keyword targets and `money_page_urls` require `is_http_url`.
  - Restore extracts fixed names only (no zip-slip, `backup/mod.rs:442-470`). Model and runtime downloads are pinned HTTPS with SHA-256 checks.
  - The toast script is constant, with data passed through env vars (`sf-ops/src/notify.rs:588-613`).
- **DoS limits:** 25 MB body limit (`sf-server/src/lib.rs:25,35`). Query limits are clamped. DOM depth is capped at 256. Crawler bodies are capped at 8 MB, 2 MB and 512 KB. LLM replies are capped at 32 KB. No regex is built from user input.
- **MCP HTTP:** a bearer token is required and forwarded, so the caller's own scopes apply (`sf-mcp/src/lib.rs:117-135`). The rmcp 3.5.1 Host allowlist defaults to loopback, which blocks DNS rebinding. `SILOFORGE_TOKEN` is preferred over a password (`sf-mcp/src/config.rs:2-3`).
