# v2.4.0 contract: SaaS readiness — new login/register, workspaces, plans & quotas, admin console

User intent: "add new login, new register, admin section, fully SaaS system get ready".
Constraint: keep single-tenant installs working exactly as today (one admin, local use). SaaS features are switched on in
Settings → Platform; defaults stay safe (registration closed, localhost binds).

## 1. Tenancy model

- **Workspaces** (`workspaces`: id, name, slug, plan_id, status active|suspended, created_at, owner_user_id, settings JSON).
  Every site belongs to a workspace (`sites.workspace_id`, migration back-fills one "Default" workspace owned by the first admin
  and moves all existing sites into it; `sites.user_id` kept for v1 compatibility = creator).
- **Members** (`workspace_members`: workspace_id, user_id, role owner|admin|member|viewer, invited_by, created_at).
  Ownership checks move from "site.user_id = me" to "I am a member of site.workspace_id with a sufficient role"
  (viewer = read only; member = run/approve/deploy; admin = settings/members/tokens; owner = billing/delete).
  Platform admins (`users.role = 'admin'`, renamed in UI "platform admin") keep full access.
- **Invites** (`workspace_invites`: email, role, token hash, expires_at, accepted_at).
- API tokens and MCP policy become workspace-scoped (token belongs to a user + workspace); existing tokens → Default workspace.
- Current workspace selected in the UI top bar (switcher); API: header `X-SiloForge-Workspace: <id>` or default = user's first.

## 2. Plans & quotas (no payment processor required)

- `plans`: id, name, limits JSON `{ sites, posts_per_site, link_runs_per_month, ai_tokens_per_month, members, api_tokens,
  schedules, auto_linker: bool, mcp: bool }`, price_label, public bool, sort. Seed: **Free** (1 site, 500 posts, 5 runs/mo,
  100k AI tokens, 1 member), **Pro** (10 sites, 5k posts, 100 runs, 2M tokens, 5 members), **Agency** (100 sites, 50k posts,
  unlimited runs, 20M tokens, 25 members), **Unlimited** (internal; the Default workspace).
- Enforcement points: site create, crawl (post cap), link-run create, AI calls (monthly token quota; uses v2.3 accounting),
  member invite, token create, schedule create. Over-limit → HTTP 402 `{error:"plan limit", limit, used}` + UI upgrade prompt.
- `usage_monthly` view/table per workspace (sites, posts, runs, ai tokens, members) shown in workspace settings and admin.
- Billing hook: `billing` settings `{provider: "none"|"manual"|"stripe", ...}`; v2.4 implements **manual** (platform admin
  assigns plans) and leaves a documented Stripe webhook interface stub (`POST /api/v2/billing/webhook` → 501 unless configured).

## 3. Auth

- **Login page** redesign (email + password, "remember me" = 30 d vs 1 d token, show/hide password, errors, lockout message,
  link to register/forgot when enabled). Optional **TOTP 2FA** (`users.totp_secret_enc`, enrolment with QR (otpauth URI rendered
  as QR in the UI), 10 recovery codes hashed).
- **Register**: modes in Settings → Platform: `closed` (default) | `invite_only` | `open`. Open/invite registration creates a user
  + (open) a new workspace on the Free plan; optional email verification (`email_verified_at`; login allowed but site creation
  blocked until verified when `require_email_verification=true`). Anti-abuse: rate limit per IP, optional allow/deny email
  domains, honeypot field.
- **Forgot / reset password** via emailed one-time link (token hashed, 1 h expiry); **change email** with re-verification.
- **Email**: SMTP settings (host, port, TLS mode, user, password write-only, from) using a pure-Rust client (`lettre` with
  rustls, no OpenSSL — verify it builds on windows-gnu; else a minimal SMTP client) + "send test email". Without SMTP, links are
  shown to platform admins in the admin console (manual delivery).
- **Sessions**: `sessions` table (id, user, created, last_seen, ip, user agent, revoked) so users can see/revoke sessions;
  JWT carries `sid`. Logout = revoke session. Keep v1 JWT compatibility (tokens without `sid` still valid until expiry).

## 4. Admin console (platform admins) — UI section "Admin"

- **Overview**: users, workspaces, sites, posts, runs today, AI tokens this month, errors, system health.
- **Users**: list/search, create, edit (name, email, role), reset password (send link), force logout, disable/enable, delete
  (with workspace ownership transfer), verify email manually, 2FA reset.
- **Workspaces**: list/search, plan, usage vs limits, members, suspend/resume, change plan, delete (soft, 30-day purge).
- **Plans**: CRUD limits.
- **Invites**, **Email/SMTP**, **Registration settings**, **Branding** (app name, logo URL, primary colour, support email,
  terms/privacy URLs shown on login/register), **Audit** (platform-wide event log filters).
- Read-only "view as workspace" for support (no impersonated writes; logged).

## 5. Workspace settings (owners/admins) — UI "Workspace"

Profile (name, slug), Members & invites (roles), Plan & usage (limits, bars, upgrade info), workspace API tokens + MCP policy
(moved from global), danger zone (transfer ownership, delete workspace).

## 6. Deployment for SaaS

- Settings → Platform: `public_url` (used in emails/links), `trust_proxy` (honour X-Forwarded-For/Proto from a reverse proxy),
  binds (e.g. `0.0.0.0:8600` behind TLS). Docs: put SiloForge behind Caddy / Cloudflare Tunnel with TLS; never expose plain HTTP;
  security checklist (registration mode, SMTP, backups, 2FA for admins).
- CORS/cookies unchanged (Bearer tokens); CSP and security headers already present.

## 7. MCP / API

- New endpoints under `/api/v2/auth/*` (register, verify-email, forgot, reset, 2fa/*, sessions), `/api/v2/workspaces/*`,
  `/api/v2/admin/*`, `/api/v2/plans`, `/api/v2/billing/*`. All logged in the event log.
- MCP: workspace-aware tools (`siloforge_workspaces_list`, `siloforge_workspace_usage`, admin tools for platform admins:
  `siloforge_admin_users_*`, `siloforge_admin_workspaces_*`) with min_scope admin.

## 8. Compatibility rules

- v1 routes keep their contract; site visibility = workspace membership (a single-user install sees exactly what it sees today).
- Existing JWTs, API tokens, Hermes MCP config keep working (Default workspace).
- All new tables via migrations; `siloforge migrate verify` unaffected.

## 9. As built (settled shapes + deviations, agent v24)

Everything above holds except where noted. Additive fields are allowed everywhere. Errors use the usual
`{error, message, statusCode}` body.

### 9.1 Tenancy, roles, headers
- Role rank viewer(1) < member(2) < admin(3) < owner(4). Platform admins (`users.role='admin'`) pass every check.
- Site-scoped routes: `GET/HEAD` need **viewer**, other methods need **member**; site create, `PATCH /api/v1/sites/{id}`,
  rotate-key, GSC connect/disconnect, Auto-Linker settings PUT need **admin**. Foreign / non-member sites → **404**
  (never 403). A suspended workspace answers non-GET site routes with 403 `workspace suspended` (platform admins
  exempt); a soft-deleted workspace's sites are invisible (404) to everyone but platform admins.
- `X-SiloForge-Workspace: <id>` selects the current workspace: it filters list routes (`GET /api/v1/sites`, `/usage`,
  `/api/v2/jobs`) and is the target for creates. Without the header, list routes show every site the caller can see
  (v1 behaviour: a platform admin sees all sites) and creates go to the caller's default workspace (platform admin →
  Default; others → first owned, else first joined). A header naming a workspace the caller is not a member of → 404
  `workspace not found` (platform admins may name any workspace).
- `X-SiloForge-View-As: <workspace id>` (platform admins only): read-only support view. Lists are scoped to that
  workspace, every non-GET request is refused with 403 `view-as is read-only`, and requests are logged
  (`admin view-as`).
- API tokens carry `workspace_id`. A non-admin user's token only reaches sites of its workspace (with the user's
  role there). A platform admin's token keeps platform-wide access (Hermes keeps working); its workspace is only the
  default create target.
- **Deviation (migration back-fill):** "Default" (id `default`, plan `unlimited`, owner = first admin; other admins
  join as admin) gets every site owned by an admin or by nobody. Each existing **non-admin** user gets a personal
  workspace `ws-<user id>` (plan `unlimited`, owner = that user) holding their own sites; their tokens move there.
  Moving everyone's sites into Default would have shown user A's sites to user B; this keeps "everyone sees exactly
  what they saw before". Existing users are marked email-verified. Fresh installs: Default is created with no owner;
  the first admin becomes its owner (`ensure_default_workspace` at boot and after the first registration).

### 9.2 Plans & quotas
- Plan ids `free`, `pro`, `agency`, `unlimited`. `limits` keys: `sites, posts_per_site, link_runs_per_month,
  ai_tokens_per_month, members, api_tokens, schedules` (integer, `null` = unlimited) and `auto_linker, mcp` (bool).
  Seed: Free 1/500/5/100000/1/1/1, auto_linker false, mcp false; Pro 10/5000/100/2000000/5/10/20, true/true;
  Agency 100/50000/null/20000000/25/50/200, true/true; Unlimited all null, true/true (public false).
- 402 body: `{error:"plan limit", message:"<human text>", statusCode:402, key, limit, used, plan, workspace_id}`.
  Points: site create (`sites`), crawl/plan enqueue + plugin sync + CSV import (`posts_per_site`: refused when the
  site already has ≥ cap posts), link-run create (`link_runs_per_month`), AI calls (`ai_tokens_per_month` = tokens
  in `model_call_log` of the workspace's sites this UTC month; over → `AiError::BudgetExhausted`, i.e. heuristics
  fallback exactly like v2.3 budgets, plus 402 on Link Run create when AI is requested and the quota is used up),
  invite create (`members`: members + pending invites), token create (`api_tokens`), schedule create (`schedules`),
  Auto-Linker enable (`auto_linker`), MCP (`mcp:false` → the MCP effective policy for that workspace is empty).
- Usage `GET /api/v2/workspaces/{id}/usage` → `{workspace_id, month:"YYYY-MM", plan:{id,name,price_label}, limits,
  usage:{sites, posts_total, posts_max_site, link_runs_month, ai_tokens_month, members, pending_invites, api_tokens,
  schedules}}`, computed live; `usage_monthly` keeps month snapshots (written by the daily maintenance pass and on
  read) for history (`?history=1` adds `history:[{month, sites, posts, link_runs, ai_tokens, members}]`).

### 9.3 Auth (`/api/v2/auth/*`)
- `GET /auth/config` (public): `{registration_mode:"closed"|"invite_only"|"open", require_email_verification,
  email_enabled, first_run, branding:{app_name, logo_url, primary_color, support_email, terms_url, privacy_url},
  version}`.
- `POST /auth/login {email, password, remember?:bool}` (default true = 30 d; false = 1 d) → `{token, user,
  session_id, expires_at}`; with 2FA on: `{two_factor_required:true, challenge}` (5-minute JWT with role `2fa`,
  refused as a credential) → `POST /auth/2fa/login {challenge, code}` (6-digit TOTP or a recovery code) → the same
  success body. 401 bad credentials, 403 `account disabled`, 429 lockout. v1 `/api/v1/auth/login` keeps its
  contract; for a 2FA user it answers 401 `two-factor authentication required; sign in through the web app`. Both
  create a `sessions` row and put `sid` in the JWT.
- `POST /auth/register {email, password, name?, invite_token?, workspace_name?, website?}` (`website` = honeypot:
  non-empty → 400) → 201 `{token, user, session_id, workspace:{id,name}|null, email_verification_required,
  verification_delivery:"smtp"|"manual"|null}`. closed → 403 `registration is closed` (first-run bootstrap still
  works); invite_only → 403 `an invitation is required` without a valid `invite_token`; domain allow/deny → 403;
  per-IP limit (`registration.rate_limit_per_hour`, default 5) → 429. Open mode creates a workspace on
  `registration.default_plan_id` (default `free`); an invite joins the inviting workspace instead. v1
  `/api/v1/auth/register` follows the same mode rules (legacy `auth.allow_registration=true` = mode `open` until the
  platform setting is saved).
- `POST /auth/verify-email {token}` (public) → `{ok:true, email}`; `POST /auth/verify-email/resend` (user) →
  `{sent, delivery}`. Unverified users may log in; site create answers 403 `email not verified` while
  `require_email_verification` is on (platform admins exempt).
- `POST /auth/forgot {email}` → always `{ok:true}` (rate-limited per IP); `POST /auth/reset {token, password}` →
  `{ok:true}`. One-time tokens are sha256-hashed in `auth_tokens`, single use, 1 h expiry (verify: 48 h); a reset
  bumps `token_version` and revokes all sessions.
- `POST /auth/change-email {new_email, password}` (session) → `{ok, pending_email, delivery}`; the emailed
  `/verify-email?token=` link switches the address and marks it verified.
- `GET /auth/me` → v1 `me` fields + `{email_verified, email_verified_at, pending_email, two_factor_enabled,
  recovery_codes_left, platform_admin, created_at, default_workspace_id, workspaces:[{id,name,slug,role,status,
  plan:{id,name}}]}`; `PATCH /auth/me {name}`.
- 2FA: `POST /auth/2fa/setup {password}` → `{secret, otpauth_uri}` (pending until enabled);
  `POST /auth/2fa/enable {code}` → `{enabled:true, recovery_codes:[10 × "xxxxx-xxxxx"]}`;
  `POST /auth/2fa/disable {password, code}` → `{enabled:false}`; `POST /auth/2fa/recovery-codes {password}` →
  `{recovery_codes}`. TOTP = RFC 6238 SHA-1, 6 digits, 30 s, ±1 step; a code is accepted once.
- Sessions: `GET /auth/sessions` → `{sessions:[{id, created_at, last_seen_at, expires_at, ip, user_agent, remember,
  current, revoked_at}]}`; `DELETE /auth/sessions/{id}` → `{revoked:true}`; `POST /auth/logout` → revokes the
  current session. JWTs without `sid` (v1 / pre-2.4) stay valid until expiry. `logout-all`, password change/reset
  and admin force-logout revoke every session.

### 9.4 Workspaces, invites, plans, billing
- `GET /workspaces[?all=1]` → `{workspaces:[{id,name,slug,role,status,is_default,owner_user_id,plan:{id,name},
  sites,created_at}], current_id}` (`all=1`: platform admins see every workspace, role `platform_admin` where not a
  member). `POST /workspaces {name, slug?}` → 201 (platform admins; others only while registration is not closed and
  they own < 3 workspaces; plan = `registration.default_plan_id`).
- `GET /workspaces/{id}` (viewer) → workspace + `my_role, limits, usage`; `PATCH {name?, slug?}` (admin);
  `DELETE {confirm:<slug>}` (owner; soft delete, `purge_after` = +30 d; Default cannot be deleted);
  `POST /workspaces/{id}/transfer {user_id}` (owner; the member becomes owner, the old owner becomes admin).
- Members: `GET /workspaces/{id}/members` (viewer) → `{members:[{user_id,email,name,role,invited_by,created_at}]}`;
  `PATCH /workspaces/{id}/members/{user_id} {role: viewer|member|admin}` (admin; the owner changes only via
  transfer; only the owner may change an admin); `DELETE` (admin, or the member themself; never the owner).
- Invites: `GET /workspaces/{id}/invites` (admin); `POST {email, role}` (admin) → 201 `{invite, delivery, link?}`
  (`link` only when delivery is `manual`); `DELETE /workspaces/{id}/invites/{invite_id}`. Public
  `GET /invites/{token}` → `{valid, email, role, workspace_name, expires_at}`; `POST /invites/{token}/accept` (user
  whose email matches, or a platform admin) → `{workspace}`. 7-day expiry.
- Workspace tokens: `GET /api/v2/tokens?workspace_id=` and `POST /api/v2/tokens {..., workspace_id?}` (default =
  current workspace; needs admin role there). Rows carry `workspace_id`.
- Workspace MCP policy: `GET/PUT /workspaces/{id}/mcp-policy` (admin) — `{tools, per_token}` like `/mcp/policy`
  minus `http_enabled` (platform-wide). The Default workspace's policy is the existing kv `mcp_policy`, so
  `/api/v2/mcp/policy` is unchanged.
- `GET /plans` (user; public plans, platform admins all) → `{plans:[{id,name,limits,price_label,public,sort}]}`.
- `GET /billing?workspace_id=` → `{provider, plan, limits, upgrade:{contact, note}}`; `POST /billing/webhook` → 501
  `billing provider not configured` (documented stub; Stripe is not implemented in 2.4).

### 9.5 Admin console (`/api/v2/admin/*`, platform admins; API tokens need `*`/`admin`)
- `GET /admin/overview` → `{users:{total,admins,disabled,unverified,with_2fa}, workspaces:{total,suspended,deleted},
  sites, posts, runs_today, ai_tokens_month, errors_open, mail:{configured, outbox_pending}, registration_mode,
  health:{version, uptime_secs, jobs:{running,queued}}}`.
- Users: `GET /admin/users?q=&limit=&offset=` → `{users:[{id,email,name,role,created_at,email_verified_at,
  disabled_at,two_factor_enabled,last_login_at,sessions_active,workspaces:[{id,name,role}]}], total}`;
  `POST /admin/users {email, name?, password?, role?, workspace_id?, workspace_role?}` → 201 `{user, delivery?,
  link?}` (no password → a set-password link is sent); `GET/PATCH /admin/users/{id} {name?, email?, role?}`;
  `POST /admin/users/{id}/{reset-password|logout|disable|enable|verify-email|reset-2fa}`;
  `DELETE /admin/users/{id}?transfer_to=<user id>` (owned workspaces + sites move to `transfer_to`, default the
  acting admin; self / last admin refused).
- Workspaces: `GET /admin/workspaces?q=&status=active|suspended|deleted&limit=&offset=` → `{workspaces:[...with
  owner, members, sites, usage, limits, deleted_at, purge_after], total}`; `GET /admin/workspaces/{id}` (+
  `members`, `sites`); `PATCH /admin/workspaces/{id} {name?, plan_id?, status?}`;
  `POST /admin/workspaces/{id}/{suspend|resume|restore}`; `DELETE /admin/workspaces/{id}` (soft delete; purged after
  30 days by the maintenance pass).
- Plans: `POST /admin/plans`, `PATCH /admin/plans/{id}`, `DELETE /admin/plans/{id}` (409 while in use).
- `GET /admin/invites` (all workspaces). Email: `GET /admin/email` → `{configured, smtp:{...,password:"***"|""},
  outbox:[{id,to,subject,kind,link,created_at,sent_at,error}]}`; `POST /admin/email/test {to}` → `{ok, delivery,
  error?}`; `DELETE /admin/email/outbox/{id}`.
- Platform settings `GET/PUT /admin/platform` → `{registration:{mode, require_email_verification, allowed_domains,
  denied_domains, rate_limit_per_hour, default_plan_id}, smtp:{host, port, tls:"starttls"|"tls"|"none", username,
  password, from_email, from_name}, branding:{app_name, logo_url, primary_color, support_email, terms_url,
  privacy_url}, deployment:{public_url, trust_proxy}, billing:{provider}}`; PUT merges per section; `"***"` keeps the
  SMTP password, `""` clears it. **Deviation:** stored in the DB (kv `platform_settings`, SMTP password encrypted
  with the secret key), not in `siloforge.toml`, so it applies live and travels with backups; it is not a section of
  `/api/v2/settings` (Settings → Platform in the UI uses `/admin/platform`).
- `GET /admin/audit?...` = `/api/v2/logs` platform-wide (same filters).
- Without SMTP every mail lands in `mail_outbox` with its link; platform admins copy links from Admin → Email.

### 9.6 Other deviations / notes (as built)
- Legacy rows: a site or token whose `workspace_id` is still NULL (written by older tools, e.g. the v1 Postgres
  migrator, before the boot pass ran) keeps v1 ownership (creator + platform admins). `siloforge serve` runs
  `tenancy::ensure_default_workspace` at boot and daily (assigns them, sets the Default owner, purges workspaces
  soft-deleted > 30 days, writes the `usage_monthly` snapshot).
- Role gates as built: site create, `PATCH /api/v1/sites/{id}` (incl. settings.auto_linker), rotate-key, GSC
  connect/disconnect and `PUT /sites/{id}/auto-linker` need workspace **admin**; creating an API token needs admin in
  the token's workspace (users without any workspace keep the pre-2.4 behaviour). Bulk decide silently skips edges
  the caller cannot write (viewer / suspended), like foreign edges in v1.
- Post cap: crawl enqueue, plugin `/sync` and CSV import answer 402 once the site holds `posts_per_site` posts; the
  crawler itself stores no new posts beyond the cap (existing posts still update). A single sync batch may cross
  the cap by up to its own size.
- AI quota: enforced inside `sf_ai::Ai::chat` (fallback to heuristics, event-log row `provider: quota`); the
  route-level 402 is raised by Link Run create only when `options.ai_refine` is true and the month is used up.
- Self-service workspace create: platform admins always; others only while registration is not `closed`, max 3
  owned. A workspace soft delete also pauses its schedules and revokes its API tokens.
- `POST /api/v1/auth/change-password` and `POST /api/v2/auth/logout-all` also revoke every session row; the fresh
  token they return has no `sid` (valid until expiry, like a v1 token).
- One-time links: reset 1 h, verify / change-email 48 h, invites 7 days; a new link of the same purpose invalidates
  older unused ones. Links use `deployment.public_url`; without it they fall back to the request Host only when
  that is an IP literal or `localhost` (a forged Host never steers a reset link), else `http://127.0.0.1:8601`.
- Sent mail is logged in `mail_outbox` without body/link; only unsent mail (no SMTP, or SMTP failed — `error` set)
  keeps the link for manual delivery. The outbox keeps the newest 2000 rows.
- `trust_proxy`: `X-Forwarded-For` (first valid IP) is used for rate limits and session IPs only when enabled.
- `GET /admin/workspaces/{id}` returns `members` as an array (list rows: a count) plus `site_list`.
- MCP: 162 tools (+7 `workspaces`, +17 `admin`); sf-mcp sends `X-SiloForge-Workspace` when `SILOFORGE_WORKSPACE`
  is set and strips links/tokens/secrets from workspace/admin tool output; `siloforge_api_request` also refuses
  `/api/v2/admin/platform` and `/api/v2/admin/email`.
- Not done in 2.4: Stripe (webhook stub only), per-workspace branding, SMTP OAuth, WebAuthn.
