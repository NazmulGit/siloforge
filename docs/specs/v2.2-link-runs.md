# v2.2.0 contract: Link Runs (guided bulk linking) + Auto-Linker

User flow (verbatim intent): crawl → see all the ideas/opportunities → tick strategies (contextual, in-text, semantic, …) →
choose the linking way (link opportunity, reverse silo, priority, …) → Run → ready (preview) → click **Deploy links** →
all links applied → results per post → each link → click to open the live page in a new tab AT the link to check it →
anything not applied → **Apply properly** (repair).

## 1. Concepts

A **Link Run** is one end-to-end batch for one site, stored in a new table `link_runs` (migration 0007) and linked to its jobs
and edges (`link_edges.run_id`, nullable, new column + index).

```
link_runs: id, site_id, name, status (draft|crawling|planning|ready|deploying|deployed|partially_deployed|failed|cancelled|undone),
  options JSON (see §2), stats JSON (opportunities, selected, applied, failed, not_present, repaired, skipped, by_strategy{}),
  crawl_job_id, plan_job_id, deploy_job_id, repair_job_id, created_by, created_at, updated_at, deployed_at, auto (bool: Auto-Linker)
```

## 2. Options (what the user ticks/chooses)

```json
{
  "crawl": "always" | "if_stale" | "skip",                // if_stale = last crawl older than 24 h
  "strategies": {                                          // checkboxes; at least one
    "in_text": true,        // native: link an existing phrase in the paragraph (no text change)
    "contextual": false,    // AI writes/rewrites one sentence that carries the link (insert module context/rephrase)
    "semantic": true,       // candidates from embedding similarity (paragraph → post)
    "keyword_rules": true,  // the site's keyword → URL rules
    "silo": true,           // links required by the chosen silo topology
    "orphan_rescue": true,  // prioritise posts with no/low contextual inbound links
    "money_pages": false,   // boost targets listed as money pages
    "fix_broken": false     // replace links to broken internal URLs with the best live target (uses link_health)
  },
  "mode": "opportunity" | "reverse" | "serial" | "priority" | "circle" | "bidirectional",
          // opportunity = best-scoring links anywhere (no silo shape); the rest = silo topologies as in the planner
  "filters": { "min_score": 0.55, "max_links_per_post": 5, "max_new_per_post": 3, "max_total": 500,
               "anchor_types": ["exact","partial","lsi","branded"], "max_exact_share": 0.35,
               "clusters": [], "include_post_ids": [], "exclude_post_ids": [], "exclude_url_patterns": [],
               "post_types": ["post","page"] },
  "ai_refine": false,
  "verify": true,                  // fetch the live page after deploy and confirm each link
  "approve": "selected"            // which suggestions deploy: "selected" (default: all that pass filters, user can untick) 
}
```

## 3. API (`/api/v2`, site ownership rules as v1; writes need write scope)

| Method | Path | Purpose |
|---|---|---|
| GET | `/sites/{id}/opportunities?limit=` | Pre-run overview: counts by strategy/type (orphans, under-linked, semantic pairs ≥ threshold, keyword-rule hits, broken internal links, silo gaps), last crawl age, posts total |
| POST | `/sites/{id}/link-runs` | Create + start a run from options → `{run}` (enqueues crawl/plan as needed; status moves crawling → planning → ready) |
| GET | `/sites/{id}/link-runs` | List runs (newest first) |
| GET | `/link-runs/{run_id}` | Run with stats, progress (`progress.phase/pct`), job ids |
| GET | `/link-runs/{run_id}/items?status=&post_id=&strategy=&q=&limit=&offset=&group=post` | Suggestions/links of the run: `{ items:[{edge_id, source:{id,title,url}, target:{id,title,url}, anchor, anchor_type, strategy, insert_module, score, status (suggested|selected|applied|failed|not_present|skipped|reverted), error, failure_kind, verify:{checked_at, present}, live_url, open_url }], total }` with `group=post` → `{ posts:[{post, links:[…]}] }` |
| POST | `/link-runs/{run_id}/select` | `{edge_ids?, all?, deselect?}` toggle which items deploy (before deploy) |
| PATCH | `/link-runs/{run_id}/items/{edge_id}` | edit anchor / pick an alternate anchor / switch module (before deploy) |
| POST | `/link-runs/{run_id}/deploy` | Approve the selected items and inject them (one deploy job); 409 if not ready |
| POST | `/link-runs/{run_id}/verify` | Re-check every applied link on the live pages |
| POST | `/link-runs/{run_id}/repair` | "Apply properly": for items failed / not_present / unverified → repair job (§4) → updated items |
| POST | `/link-runs/{run_id}/undo` | Undo every link this run applied (exact removal) |
| POST | `/link-runs/{run_id}/cancel` | Cancel while crawling/planning/deploying |

`open_url` = the live post URL + a text fragment that scrolls to and highlights the link in Chrome/Brave/Edge:
`<post url>#:~:text=<percent-encoded anchor>` (use `prefix-,anchor` form when the anchor appears more than once, prefix = up to
3 words before the anchor in the paragraph). `live_url` = plain URL.

## 4. Repair ("Apply properly") per item, in order

1. Re-fetch raw content; if the link is actually present (verify was wrong/cached) → `applied`.
2. Re-locate the paragraph by hash, then by anchor text search across the post; insert there (native).
3. Try the edge's alternate anchors (anchor picker `alternates`) in the original or a nearby paragraph.
4. If `contextual` is enabled for the run and an AI chain is available → context/rephrase module with validated output.
5. Otherwise → `skipped` with a clear reason (`anchor text no longer in post`, `post locked/changed`, `no WP credentials`, …).
Every attempt is journaled (inject journal) and logged; verify runs after repair.

## 5. Auto-Linker (scheduled runs)

Per-site config in site settings `auto_linker`: `{ enabled, cron, tz, options (same as §2), live: false (dry-run default),
max_per_day, pause_on_failure_rate: 0.2 }`. A scheduler job kind `link_run` creates a run with `auto=true`; when `live=false`
it stops at `ready` and notifies ("N links ready to deploy"); when `live=true` it deploys + verifies + repairs once and notifies a
summary. Auto-pause (sets enabled=false + notification) when the failure rate exceeds the threshold. All in Logs.

## 7. UI

- New **Link Run** page in the Site group (`/sites/:id/link-run`, also "New Link Run" button on Dashboard and Tools):
  a stepper — **1 Crawl** (status + "crawl now"/"use last crawl"), **2 Opportunities** (cards with counts per strategy),
  **3 Strategies** (checkboxes with one-line explanations + filters), **4 Linking mode** (cards: Link opportunity, Reverse silo,
  Serial, Priority, Circle, Bidirectional — each with a small diagram), **5 Run** (progress bar with phases),
  **6 Review** (grouped by post; untick/edit anchor/choose alternate; counts; "Deploy N links" primary button),
  **7 Deploy** (progress), **8 Results** (per post → links: status badge, anchor, target, **Open ↗** opens `open_url` in a new
  tab, "Verify again", filters: applied/failed/not present), **9 Fix** ("Apply properly to N items" → repair, then results refresh).
- **Runs history** list per site (status, counts, when, by whom/auto) with Undo run.
- **Auto-Linker** card in site settings (enable, schedule, dry-run/live switch, caps, same options as the wizard).

## 8. Backend as built (settled shapes + deviations, backend agent be22)

**Responses.** `POST /sites/{id}/link-runs` → 201 `{run, job_run_id}`. `GET /sites/{id}/link-runs?limit=` → `{runs, total}`.
`GET /link-runs/{id}` → the run object itself. `POST .../deploy|verify|repair|undo` → 202 `{run, job_run_id}` (409 on a
wrong status; deploy needs `ready`). `POST .../cancel` → `{run}` (409 unless draft/crawling/planning/deploying).
`POST .../select` → `{changed, run}`. `PATCH .../items/{edge_id}` → `{item, run}`. Foreign/unknown/non-uuid run → 404.

**Run object.** `{id, site_id, name, status, options (defaults filled in), stats, error, crawl_job_id, plan_job_id,
deploy_job_id, repair_job_id, verify_job_id, undo_job_id, current_job_id, created_by, created_at, updated_at, deployed_at,
auto, progress, job_running}`. `stats = {opportunities, selected (ticked), applied, failed, not_present, repaired, skipped,
reverted, pending (ticked/approved, not yet written), suggested (unticked), by_strategy: {<strategy>: {total, selected,
<item status>: n}}}`, computed live. `progress = {phase, pct, step?, job_status?}`: while the job runs `phase` is the
pipeline phase (crawl/chunk/embed/.../anchors/save/keyword_rules/fix_broken/select/inject/verify/relocate/...), `step` the
run status; idle runs report `{phase: <status>, pct: 100}`. All job ids are pollable like any job (`/api/v1/jobs/run/:id`).

**Statuses.** No extra statuses: `repair` and `undo` run under `deploying` (then back to deployed/partially_deployed/failed,
or `undone`); `verify` keeps the status (and recomputes it). Final deploy status: `deployed` = every ticked item applied
and present, `partially_deployed` = some, `failed` = none (also: no WP credentials → items stay `selected` for the plugin).
A run stuck in an active status whose job ended is reconciled to failed/cancelled on read. One active run per site (409).

**Jobs.** One job kind `link_run` (payload `{link_run_id, step: plan|deploy|verify|repair|undo}`) drives every step; the
crawl runs inline in the plan job (like `audit`), so `crawl_job_id == plan_job_id`; deploy calls the inject pipeline
inline (no separate inject job). No `link_run_id` = Auto-Linker run (scheduler payload `{auto: true}`; a bare
`/api/v1/schedules` row of kind `link_run` works too). Hard timeout 4 h. Schema 0007 adds `link_runs.error,
verify_job_id, undo_job_id, current_job_id` and `link_edges.run_selected, verified_at, verify_present` besides
`link_edges.run_id`; `site_schedules.job_kind` accepts `link_run` (table rebuilt in the migration transaction).

**Strategies.** `in_text` / `contextual` = how links are inserted (≥ 1 required): in_text = the anchor already occurs in
the paragraph → `native` (regardless of the plan's module threshold); contextual = `context`/`rephrase` (AI sentence).
`semantic`, `keyword_rules`, `silo`, `fix_broken` = candidate sources (≥ 1 required); `silo` needs a topology mode (not
`opportunity`). `orphan_rescue` (target contextual orphan or ≤ 1 body inbound) and `money_pages` = score boosts ×1.15
(cap 1.0, applied before `min_score`). `score_breakdown.strategy` = the source strategy; `score_breakdown.strategies` =
source + boosts + insertion method (the `strategy=` item filter matches either). `approve` accepts `selected` (default),
`all`, `none`. Unknown option keys are rejected (400).

**Plan / adoption.** The run plans with its scope (opportunity = semantic candidates only, no topology), then adopts the
site's pending suggestions (origins plan/archive/keyword_linker/link_run, not held by another active run) that match the
strategies and the hard filters (post_types, anchor_types, clusters, include/exclude ids, url patterns: `*` glob or
substring, min_score). The caps (max_new_per_post, max_links_per_post incl. existing links, max_total, max_exact_share)
decide only which items are ticked. `score_breakdown.alternates = [{anchor, anchor_type, in_paragraph}]` is stored for
every plan (not only runs); items expose `alternates: [string]`.

**fix_broken.** Uses existing `link_health` rows (run Link Health first; the run does not run it). Target = best live post
by URL-slug word coverage (≥ 0.5; ties: slug Jaccard, then cosine to the source). Edge origin `link_run`,
`score_breakdown.replace_href` = the broken href; a pending plan suggestion for the same pair is dropped. Inject re-points
the existing link (`sf_engine::insert::replace_link`, href value only); undo writes the old href back (byte-identical when
the original href needed no HTML escaping).

**Items.** Item fields as §3 plus `strategies, selected, replaces (broken href), repaired, applied_at`. Status mapping:
suggested (unticked) · selected (ticked, or approved and waiting) · applied · not_present (applied, live check said
missing) · failed · skipped (repair gave up, or rejected) · reverted. `verify.present` is null when the check was
inconclusive. `group=post` → `{posts: [{post, counts, links}], total (posts), total_items}`, paging over posts.
`open_url`: kept unencoded only `A-Z a-z 0-9 . _ ~ ! * ' ( )`, everything else `%XX` (incl. `-`, `,`, `&`, space); the
prefix form uses up to 3 words before the first whole-word, case-insensitive occurrence when the anchor occurs more than
once in the paragraph. PATCH item body: `{anchor}` | `{alternate: "<one of alternates>" | index}` | `{insert_module:
native|rephrase|context}`; 409 unless the run is ready and the item suggested.

**Repair** follows §4; attempts are appended to `score_breakdown.repair` (+ `repaired: true`); skip reasons: `anchor text
no longer in post`, `post locked/changed`, `no WP credentials`, `post has no WordPress id`, `WordPress write failed (...)`,
`the paragraph already links to the target`, `link did not appear on the live page`.

**Opportunities.** `{site_id, posts_total, last_crawl_at, last_crawl_age_hours, crawl_stale, counts: {orphans,
contextual_orphans, under_linked, semantic_pairs, keyword_rule_hits, broken_internal, silo_gaps, money_pages}, by_strategy:
{in_text, contextual, semantic: {pairs, threshold, estimated, posts_with_embeddings, pending}, keyword_rules: {rules, hits,
pending}, silo: {gaps, pending}, orphan_rescue: {...}, money_pages: {...}, fix_broken: {broken_links, posts, pending}},
pending_suggestions}`. `?min_score=` (default 0.55) = cosine threshold; exact up to 1500 posts with embeddings, else
estimated from a sample (`estimated: true`).

**Auto-Linker (additions).** Endpoints `GET /sites/{id}/auto-linker` → `{auto_linker (defaults filled), configured,
schedule: {active, cron, tz, next_run_at, last_run_at, last_job_run_id} | null, last_run}`, `PUT` (merged into the stored
object; null removes a key; enabling clears `paused_reason`) and `POST /sites/{id}/auto-linker/run` → 202 `{job_run_id}`
(works while disabled, cap applies). v1 `PATCH /api/v1/sites/{id}` accepts `settings.auto_linker` (validated: cron, IANA
tz, options, max_per_day 1..10000, pause_on_failure_rate 0..1) and syncs the `link_run` schedule row (disabled = row
inactive). Extra field `paused_reason`. Daily cap = applied links of auto runs since 00:00 UTC; an auto run's
`filters.max_total` is capped to the remaining budget. Failure rate = (failed + not_present + skipped) / ticked after the
repair pass. Notification events `link_run.ready` (dry run), `link_run.done` (deploy summary, manual and auto),
`auto_linker.paused` (warn). Event log actions `link_run created|<status>|<step> queued|verified|repaired|auto_linker paused`.

**MCP.** 15 tools in category `link_runs` (the 12 of §6 + `siloforge_link_runs_list`, `siloforge_link_run_item_update`,
`siloforge_link_run_cancel`); deploy/repair/undo are destructive with `confirm: true`; total 133 tools.

**E2E changes (2026-10-14, docs/testing/link-runs-e2e.md).** Item status: an approved item that deploy could not place
(`failure_kind=content_gap`) reports `failed`. `alternates` of an in-text run (Contextual off) list only phrases that
occur in the paragraph, and `PATCH {anchor}` with a phrase that is not in the paragraph → 400 in such runs. `ready` runs
hold their items (a newer run does not adopt them) and can be cancelled (`POST .../cancel` → `cancelled`, items free).
Run object adds `created_by_name`. `open_url` always carries safe context: `prefix-,anchor,-suffix` (≤ 3 words each;
punctuation or a typographic possessive glued to the anchor belongs to the term; straight quotes/dashes end the context).
Contextual runs hand native items that cannot be placed to the AI (`InjectOpts.llm_fallback`); AI edits are recorded in
`score_breakdown.llm_edit` and undo removes the inserted sentence / restores the rephrased paragraph exactly. Verify sets
`error = "link not found on the live page"` when the check says missing. Opportunities' orphan counts are computed from
the committed links (no plan needed) and `threshold` is rounded.
