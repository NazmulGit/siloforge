# v2.3.0 contract: AI task tiers, token accounting, "Always use AI", token minimisation

User intent: main AI = local Codex proxy model (gpt-6-luna or lower), fallback Haiku or lower; split work into segments —
**low** tasks (cheap), **main** tasks, **high-priority** tasks (stronger model) — to minimise token use; show AI token consumption
in Logs; a setting "Always use AI model for perfect linking"; other improvements where possible.

Already configured in production (2026-10-14): providers `codex-proxy` (http://127.0.0.1:8791/v1, dedicated client key "SiloForge",
allowed gpt-6-luna, gpt-5.6-luna, gpt-6-sol) and `dario` (http://127.0.0.1:3460/v1); models gpt-6-luna, gpt-5.6-luna, gpt-6-sol,
claude-haiku-4-5, claude-haiku-5-5; active global chat chain "Main: Luna -> Haiku" (gpt-6-luna → claude-haiku-4-5).

## 1. Tiers

- `model_chains.tier` TEXT NOT NULL DEFAULT 'main' CHECK IN ('low','main','high') (migration; existing chains → main). The
  "one active chain per scope" rule becomes per (role, tier, site|global).
- Resolution: site chain for the tier → global chain for the tier → **main** chain (site → global) → env fallback.
- Defaults seeded at upgrade if absent: **low** = gpt-5.6-luna (reasoning low) → claude-haiku-4-5; **main** = existing
  Luna → Haiku chain; **high** = gpt-6-sol → claude-haiku-5-5 → gpt-6-luna.
- Every AI call declares a task and its tier (mapping configurable in settings `ai.task_tiers`):
  | task | default tier | what |
  |---|---|---|
  | `anchor_pick` | low | choose/propose anchor among candidates (batched) |
  | `relevance_check` | low | judge source→target relevance 0–1 (batched) |
  | `link_verify_judge` | low | ambiguous verification decisions |
  | `rephrase` | main | rewrite a sentence to carry the link |
  | `context_sentence` | main | write a new bridging sentence |
  | `repair_insert` | main | "Apply properly" AI fallback |
  | `money_page` / `priority` | high | any task where the target is a money page or the run/site is marked high priority |
- Per-call options: `reasoning_effort` (low|medium|high) passed to OpenAI-compatible providers that support it (codex models);
  `max_tokens` tight per task (anchor 60, relevance 80, sentence 220).

## 2. Token minimisation

- **Batching**: low-tier tasks send up to N (default 20) edges per request with a compact JSON schema; responses parsed per item.
- **Cache**: `ai_cache` table keyed by sha256(task, model family, prompt-relevant inputs: paragraph hash, target id + title hash,
  candidates) → result JSON, TTL 30 days; cache hits cost 0 tokens (logged as cache hits).
- **Skip rules**: no AI call when the heuristic is already confident (anchor score ≥ τ_high, relevance by embedding ≥ τ_high),
  configurable thresholds; only borderline items go to AI.
- **Prompt compaction**: strip HTML, cap paragraph to ~600 chars around the candidate window, short system prompts.
- **Budgets**: daily token budget per tier and per site (settings `ai.budget`); when exhausted → heuristic only + notification;
  per-run budget shown before a Link Run starts (estimated tokens/cost from counts × average).

## 3. Token accounting & visibility

- `model_call_log` rows always carry tokens_in/out (from provider `usage`; estimate with chars/4 when absent, flagged
  `estimated`), plus `task`, `tier`, `site_id`, `run_id`, `cache_hit`, `cost_usd` (from models.price_in/out per 1M; 0 for local
  proxies unless prices are set).
- Event log (§9 of v2.1): new source **`ai`** with action `ai <task> <model>`, detail `{tier, tokens_in, tokens_out, cost_usd,
  cache_hit, fallback_used, rung, latency_ms}`; Logs page gets an "AI" chip + token columns + totals in the stats header.
- `GET /api/v2/ai/usage?since=&group=day|model|tier|task|site` → rows `{key, calls, tokens_in, tokens_out, cost_usd, cache_hits,
  errors}` + totals; Settings → AI Models gets a **Usage** panel (charts by day/tier/model, top sites, cache hit rate, budget bars).
- MCP: `siloforge_ai_usage`, `siloforge_ai_settings_get/update`.

## 4. "Always use AI for perfect linking"

Settings → AI Models → `ai.always_on` (default false; the user wants it ON in production):
- every plan / Link Run uses AI anchor refinement + AI relevance check for every borderline candidate (low tier, batched,
  cached), AI insertion allowed for contextual items (main tier), money-page targets on high tier;
- respects budgets; if the AI chain is down or budget exhausted, falls back to heuristics automatically and says so in the run
  stats and notification;
- shows estimated tokens before starting a run.

## 5. Settings shape (`GET/PUT /api/v2/settings`, new section `ai`)

```json
"ai": { "always_on": false, "task_tiers": {"anchor_pick":"low", ...}, "batch_size": 20,
        "confidence_skip": {"anchor": 0.85, "relevance": 0.80},
        "budget": {"daily_tokens": {"low": 2000000, "main": 1000000, "high": 300000}, "per_site_daily_tokens": 300000},
        "cache_ttl_days": 30, "reasoning_effort": {"low": "low", "main": "low", "high": "medium"} }
```
UI: Settings → AI Models gets tabs **Chains by tier** (low/main/high editors with drag-reorder rungs), **Task routing**,
**Budgets & cache**, **Usage**; plus the "Always use AI" switch with a short explanation and the estimate.

## 6. Backend as built (settled shapes + deviations, agent v23)

Everything above holds except where noted. Additive fields are allowed everywhere.

**Schema (migration 0008_ai_tiers).** `model_chains.tier` (CHECK low|main|high, default main); the active-chain unique
indexes are now per (role, tier, site) / (role, tier). `model_call_log` gains `task, tier, site_id, run_id, cache_hit (0/1),
cost_usd REAL, estimated (0/1), items INTEGER DEFAULT 1` (items = edges carried by a batched call, or cache hits served by
one cache row), `model_id` (wire id; also for env rungs) + indexes on (called_at, tier), (site_id, called_at), (run_id).
New `ai_cache(key PK, task, family, result JSON, created_at, expires_at, hits)`. Cache-hit rows are written to
`model_call_log` with `provider='cache'`, `ok=1`, tokens 0, `cache_hit=1`, `items=<hits>`.
`run_id` = the Link Run id for link_run jobs, otherwise the job run id (plain plan/inject jobs).

**Seeding.** At `serve` start (`sf_ai::seed_tier_chains`, once: kv `ai_tiers_seeded`): needs providers named
`codex-proxy` and `dario`; when either is missing seeding is skipped with an info log (kv not set, retried next boot).
Missing model rows (`gpt-5.6-luna`, `gpt-6-sol`, `gpt-6-luna` under codex-proxy; `claude-haiku-4-5`, `claude-haiku-5-5`
under dario, role chat) are created. Creates and activates global chat chains "Low: Luna 5.6 -> Haiku 4.5" (tier low) and
"High: Sol -> Haiku 5.5 -> Luna" (tier high) unless an active global chain for that tier exists. Existing chains stay `main`.

**Chains API (v1 routes, additive).** Chain rows carry `tier`; `POST /api/v1/model-chains` accepts `tier` (default main);
`PATCH` accepts `tier` (an active chain moved to a tier deactivates the active sibling there); `GET ?tier=` filters;
activation is unique per (role, tier, site|global). `GET /api/v2/ai/tiers?site_id=` (admin) →
`{tiers: [{tier, chain_id, chain_name, source: site|global|env|none, resolved_from: "tier"|"main"|"env"|"none",
reasoning_effort, rungs: [RungInfo]}]}` = the effective chain per tier.

**Tasks.** `anchor_pick` (batched, also returns relevance), `relevance_check` (batched, for edges whose anchor is confident but
relevance borderline), `link_verify_judge` (reserved: routed + accounted, no caller yet), `rephrase`, `context_sentence`,
`repair_insert` (the AI module during Apply properly), `money_page` (tier override when the target is a money page:
`posts.meta.money_page`), `priority` (tier override when the run option `high_priority: true` or site setting
`ai_high_priority: true`). Max tokens: anchor_pick 60/item, relevance_check 80 + 20/extra item, sentences 220.
`reasoning_effort` is sent only to OpenAI-shaped providers for models whose id starts with `gpt-5`, `gpt-6`, `o1`, `o3`,
`o4` or contains `codex` (value `none` = not sent).

**Skip rules.** anchor confidence = the heuristic pick score normalised 0..1 (semantic cosine when known, else lexical
score); relevance = the edge's semantic cosine (source paragraph → target), else the composite score. Both ≥ thresholds →
no AI call (counted as `skipped_confident`). Without `always_on` and without `ai_refine` nothing is sent.

**Budgets.** "today" = UTC day; usage = tokens_in + tokens_out of non-cache rows. Limit 0 = unlimited. When a tier or the
site is over budget `Ai::chat` returns `AiError::BudgetExhausted` without calling a provider; callers keep heuristics, the
plan/run stats say `ai.fallback = "budget exhausted"`, and one notification `ai.budget_exhausted` (warn) is sent per UTC
day per tier / per site, plus an event-log row (source `ai`, status error).

**Settings `ai`.** GET returns the §5 shape (all 8 tasks in `task_tiers`). PUT merges nested objects (e.g.
`{"ai":{"task_tiers":{"rephrase":"high"}}}`). Validation: tiers ∈ low|main|high, unknown tasks rejected; batch_size 1..50;
confidence_skip.* 0..1; daily_tokens.* and per_site_daily_tokens 0..10 000 000 000 (0 = unlimited); cache_ttl_days 0..365
(0 = cache off); reasoning_effort.* ∈ none|low|medium|high. Persisted to `[ai]` in siloforge.toml (inline tables).

**Usage.** `GET /api/v2/ai/usage?since=7d&until=&group=day|model|tier|task|site|provider&site_id=&run_id=` (admin) →
`{group, since, until, rows: [{key, label?, calls, items, tokens_in, tokens_out, cost_usd, cache_hits, errors, estimated}],
totals: {calls, items, tokens_in, tokens_out, cost_usd, cache_hits, errors, estimated, cache_hit_rate},
budget: {day, tiers: {low|main|high: {used, limit, remaining (null = unlimited), exhausted}}, per_site_limit,
sites: [{site_id, name, used, limit, exhausted}] (top 10 today)}}`. `calls` excludes cache rows; `cache_hit_rate` =
cache_hits / (cache_hits + items of real calls).

**Event log.** Source `ai` (added to the source list and `/logs?source=ai`), actor `system`, action `ai <task> <model>`
(`ai <task> cache` for cache hits), target = run_id, site_id, status ok|error, duration_ms = latency, detail
`{tier, task, tokens_in, tokens_out, estimated, cost_usd, cache_hit, items, fallback_used, rung, latency_ms, provider, run_id}`.
`GET /logs/stats` adds `ai: {calls, tokens_in, tokens_out, cost_usd, cache_hits}` for the same window.

**Link Runs.** Run option `high_priority` (bool, default false) added; `ai_refine` is now honoured by the run's plan step
(it was not forwarded in 2.2). `always_on` turns AI refinement on for every plan and run. Estimate:
`POST /api/v2/sites/{id}/link-runs/estimate` body `{options}` (same as create; also accepts the bare options object) →
`{ai_enabled, always_on, items_estimated, ai_items: {anchor_pick, relevance_check, contextual}, calls, tokens_in, tokens_out,
tokens_total, cost_usd, by_tier: {low|main|high: {calls, tokens, cost_usd}}, budget: {low|main|high: remaining|null, site:
remaining|null}, within_budget, basis: "history"|"defaults", note}`. Averages come from the last 30 days of
`model_call_log` per task (≥ 5 calls) else defaults (anchor_pick 260 in / 30 out per item, relevance 140/12, sentence
600/120). The run object gains `ai: {calls, items, tokens_in, tokens_out, cost_usd, cache_hits, errors, estimated,
by_task: {<task>: {calls, tokens_in, tokens_out}}, asked, skipped_confident, fallback}` (from `model_call_log` by run_id +
kv `ai_run:<id>`).

**AI settings routes.** Besides `GET/PUT /settings` (section `ai`), `GET/PUT /api/v2/ai/settings` (admin) read/write the
`ai` section alone (PUT body = the section; answer = the section + `changed`).

**MCP.** `siloforge_ai_tiers`, `siloforge_ai_usage`, `siloforge_ai_settings_get`, `siloforge_ai_settings_update` (admin,
`confirm` not required; they use `/ai/tiers`, `/ai/usage`, `/ai/settings`), `siloforge_link_run_estimate` (link_runs); chain
tools take `tier` → 138 tools.

**Other deviations / notes.**
- `rephrase` returns the whole paragraph, so its `max_tokens` is ~chars/3 + 60 (min 220, max 2000) instead of a flat 220;
  `context_sentence` is 220. A budget-blocked call writes no `model_call_log` row (only an event-log row, status error).
- Every chat call emits one event-log row (cache hits: one row per batch of hits); `ai` rows carry no `user_id`, so only
  admins see them in Logs.
- Estimate shares are fixed: 60 % of items → anchor_pick, 25 % → relevance_check (rest skipped as confident), 30 % of
  items need an AI sentence when `contextual` is ticked; items = min(max_total, posts × max_new_per_post); billable
  low-tier items are reduced by the 30-day cache hit rate.
- `ai_run:<id>` kv summaries and expired `ai_cache` rows are pruned by the daily `maintenance` job (90 days / TTL).
- With reasoning models a tight `max_tokens` can include reasoning tokens; watch `errors` in `/ai/usage` after enabling
  `reasoning_effort` above `low` and raise the effort to `none` for a tier if empty replies appear.
- Live smoke (dario, claude-haiku-4-5, 2 calls): batched anchor_pick + relevance_check parsed; dario reports ~1.5-1.7k
  input tokens per call (its own system prompt), so per-item averages from history are larger than the defaults.
