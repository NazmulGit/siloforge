# v2.1.0 contract: Settings, resources, CPU/GPU balancing, API & MCP, Docs, Downloads, plugin

Authoritative interface between the backend (BE), UI and docs work for v2.1.0. All routes live under `/api/v2`,
return JSON (except file downloads), and use `ApiError` for errors. "admin" = `Admin` extractor; "user" = any logged-in user.
Never return secrets: any secret field is write-only and is reported as `"***"` (set) or `""` (unset).

## 1. Settings — `GET /api/v2/settings` (admin), `PUT /api/v2/settings` (admin)

GET returns:
```json
{
  "resources": { "cpu_threads": 0, "cpu_threads_effective": 6, "logical_cpus": 24, "max_concurrent_jobs": 3,
                 "vector_cache_mb": 512, "max_memory_mb": 0, "low_priority_jobs": true, "defer_when_cpu_above": 0.0,
                 "mem_total_mb": 65448 },
  "compute":   { "embed_mode": "auto", "gpu_enabled": true, "gpu_available": true, "gpu_name": "AMD Radeon RX 5700 XT",
                 "hybrid_gpu_share": 0.7, "embed_batch_size": 64, "embed_chain": ["onnx","remote","remote2"],
                 "remote_model": "sentence-transformers/all-minilm-l6-v2", "remote_key_set": true, "remote_key2_set": false,
                 "active_device": "directml" },
  "wordpress": { "default_insert_modules": ["native"], "verify_after_inject": true, "default_max_links_per_post": 10,
                 "default_min_links_per_post": 0, "max_new_links_per_pass": 5, "request_timeout_ms": 20000,
                 "user_agent": "SiloForge/2.1.0 (+internal-linking)" },
  "crawl":     { "concurrency": 4, "timeout_ms": 20000, "max_pages": 20000, "allow_private_hosts": false },
  "llm":       { "fallback_url": "http://127.0.0.1:3460/v1", "fallback_models": ["claude-sonnet-5-5"], "timeout_ms": 120000 },
  "server":    { "binds": ["127.0.0.1:8600","127.0.0.1:8601"], "cors_origins": [], "allow_registration": false,
                 "mcp_http_enabled": true },
  "backup":    { "dir": "D:/Backups/SiloForge", "keep": 10, "schedule": "17 3 * * *", "passphrase_set": true },
  "monitor":   { "sample_secs": 5, "retain_days": 14, "alert_cpu_pct": 95.0, "alert_mem_pct": 92.0, "alert_disk_free_mb": 2048 },
  "restart_required": [],
  "restart_supported": true
}
```
- `embed_mode`: `auto` (GPU if available else CPU, remote as fallback) | `gpu` | `cpu` | `hybrid` (GPU and CPU work on the same job
  in parallel; GPU takes ~`hybrid_gpu_share` of batches via work-stealing) | `remote` (OpenRouter-style provider first).
- `max_memory_mb`: soft cap for the process (0 = off). When exceeded, the vector cache is shrunk and heavy jobs are deferred.
- PUT body: any subset `{ "<section>": { "<key>": value } }`. Validates every key (ranges: cpu_threads 0..logical_cpus,
  max_concurrent_jobs 1..16, vector_cache_mb 64..32768, max_memory_mb 0 or 256..mem_total, defer_when_cpu_above 0..100,
  hybrid_gpu_share 0.1..0.9, embed_batch_size 8..512, crawl.concurrency 1..32, backup.keep 1..365, valid cron, etc.).
  Persists to `<home>/siloforge.toml` preserving comments (toml_edit). Applies live where possible (max_concurrent_jobs,
  defer_when_cpu_above, low_priority_jobs, vector_cache_mb, max_memory_mb, embed_mode/hybrid share/batch, crawl.*, wordpress.*, llm.*,
  backup.*, monitor.*); keys that need a restart (binds, cpu_threads pool size) are listed in `restart_required`.
  Secret keys (`compute.remote_key`, `compute.remote_key2`, `backup.passphrase`) are write-only and go to `secrets.env`.
  Returns the same shape as GET.
- `POST /api/v2/system/restart` (admin) → `202 {"restarting":true}`: the process re-launches itself (spawn the keepalive task / new
  process after releasing the instance lock), so a restart takes seconds, not up to 5 minutes.

## 2. API tokens — editable

- Existing: `GET/POST /api/v2/tokens`, `DELETE /api/v2/tokens/:id`.
- New `PATCH /api/v2/tokens/:id` (owner or admin) body `{ name?, scopes?, expires_in_days?: number|null }` → updated row.
  Rules: scopes ⊆ ["*","read","write","admin"]; `admin`/`*` only for admins; a token can never be raised above its parent's scopes;
  changing scopes clears the auth cache so it applies immediately. Rows gain `parent_id`, `tool_policy` (see §3).

## 3. MCP management

- `GET /api/v2/mcp` (user): `{ enabled, http_enabled, stdio_command, stdio_args, http_url, api_url,
  tools: [{ name, title, description, read_only, destructive, min_scope, enabled }] }`.
- `GET /api/v2/mcp/policy`, `PUT /api/v2/mcp/policy` (admin): `{ http_enabled: bool, tools: { "<tool name>": { enabled: bool,
  min_scope: "read"|"write"|"admin" } }, per_token: { "<token id>": { allow: ["tool", ...] | null } } }`. Stored in `kv`.
- Enforcement in sf-mcp (both stdio and HTTP): fetch the policy from `GET /api/v2/mcp/policy/effective` (user; returns the policy
  for the calling credential: allowed tool names) at session start and every 60 s; `tools/list` shows only allowed tools;
  `tools/call` of a disabled/insufficient-scope tool returns an MCP error. HTTP `/mcp` returns 404 when `http_enabled=false`.
- `GET /api/v2/mcp/stats` (admin): per tool `{ name, calls_24h, errors_24h, last_called_at }` (record calls via an audit row or kv).

## 4. Docs

- Built-in user guide embedded in the binary from `docs/guide/*.md` (front matter: `title`, `section`, `order`).
- `GET /api/v2/docs` (user) → `{ docs: [{ slug, title, section, order }] }`; `GET /api/v2/docs/:slug` → `{ slug, title, section, markdown }`.
- UI: a "Docs" menu entry with a two-pane reader, plus a "?" button in the top bar and on each page that opens the matching
  doc in a right-side drawer (page → slug map in the UI).

## 5. Downloads

- `GET /api/v2/downloads` (user) → `{ downloads: [{ file, kind: "app"|"wp-plugin", version, size_bytes, sha256, created_at,
  latest: bool }], current_version }`. Source dir: config `[downloads] dir` (default `<exe dir>/../releases`, i.e.
  `D:\Final_Apps\SiloForge\releases`); recognises `siloforge-<ver>-windows-x64.zip` and `siloforge-connect-<ver>.zip`
  (+ `.sha256`). `GET /api/v2/downloads/:file` streams the file (only names from the listing; no paths) with Content-Disposition.
- UI: "Downloads" page: latest app + plugin with version, size, SHA-256, download buttons, older versions list, install notes.

## 8. Full agent capability over MCP (Hermes manages everything)

Goal: an AI agent (Hermes) can do through MCP everything an admin can do in the UI, with scope gating and safety.
- Keep the 28 existing tool names unchanged. ADD tools so every UI/API capability is reachable, grouped by prefix:
  sites (`siloforge_site_get/update/delete/rotate_key/set_wp_credentials`), crawl/plan/audit/link_health/gsc run + status,
  edges (`list/get/decide/bulk_decide/edit_anchor/score_breakdown`), inject/undo, rules (keyword rules + ignore list CRUD),
  schedules CRUD + run-now, reports (links, anchors, orphans, cannibalization, metrics trend, link health summary, CSV export),
  silo/clusters (list/import/export), posts (list/search/get), AI models (providers/models/chains/rungs CRUD + probe + status),
  settings (`siloforge_settings_get/update`, resources & compute), system (status, metrics, restart, doctor-lite),
  jobs (list/get/logs/cancel/wait), backups (create/list/verify/delete), notifications (channels CRUD/test, list/read),
  tokens (list/create/update scopes/revoke — admin only), MCP policy (get/update), logs (`siloforge_logs_query`), docs
  (`siloforge_docs_list/get` so the agent can read the user guide), downloads (list).
- Every tool declares `read_only`/`destructive` annotations and `min_scope` (read/write/admin); destructive tools
  (delete site, bulk inject, undo, restore-like, token revoke) require an explicit `confirm: true` argument.
- Escape hatch: `siloforge_api_request {method, path, query?, body?}` limited to `/api/v1/*` and `/api/v2/*`, admin scope,
  disabled by default in the MCP policy.
- `siloforge_capabilities` returns the tool catalogue grouped with short usage notes and typical workflows
  (crawl → plan → review → approve → inject → verify → undo), so an agent can self-orient.
- All tools obey the MCP policy (§3) and are recorded in the unified log (§9).

## 9. Unified logs ("Logs" page, Workspace group)

Everything that happens is recorded in one append-only `event_log` (new migration), retained by `monitor.event_log_retain_days`
(default 90), indexed by ts/source/actor/site:
`{ id, ts, source: "ui"|"api"|"mcp"|"job"|"system"|"auth"|"notify", actor (user:<id> | token:<name> | mcp:<token> | system),
   action (e.g. "PATCH /api/v1/sites/{id}", "tool siloforge_plan_site", "job plan done", "login failed"), target (site/job/edge id),
   site_id, status ("ok"|"error"|"denied"), http_status, duration_ms, detail (JSON, NO bodies/secrets) }`
- Writers: an axum middleware for every /api request (via = ui for browser JWT sessions, api for API tokens, mcp when the
  request carries `X-SiloForge-Via: mcp` + tool name header set by sf-mcp), MCP tool calls (start/end, ok/error), job lifecycle
  (queued/started/done/failed/cancelled with stats summary), auth events (login ok/failed, lockout, token create/revoke),
  notifications sent, system events (start/stop/restart, settings changed, backup done/failed, errors). Writes batched off the
  request path (mpsc → writer every 1 s) so logging never slows requests. Health/static/poll GETs may be sampled or skipped
  (configurable `log_reads: false` default: log all non-GET + all MCP + errors; GETs only when `log_reads=true`).
- `GET /api/v2/logs?source=&actor=&site_id=&status=&q=&since=&until=&limit=&before_id=` (admin; users see only their own) →
  `{ logs: [...], next_before_id }`; `GET /api/v2/logs/export?…` → CSV; `GET /api/v2/logs/stats?since=` → counts by source/status.
- UI "Logs" page: filter chips (source, status), actor/site selectors, search box, time range, live tail toggle (poll 3 s),
  row expand to see detail JSON, export CSV. Job rows link to the job log drawer.


## 10. Backend implementation notes and deviations (v2.1.0, settled by the BE)

Everything above holds except where noted here. Additive fields are allowed everywhere.

**§1 Settings**
- Live config: `sf_core::LiveConfig` (an `Arc<Config>` behind a lock + change listeners). The runner (max_concurrent_jobs,
  defer_when_cpu_above, memory cap), scheduler (maintenance_cron), backup scheduler (schedule/dir/keep/passphrase),
  monitor (sample_secs, alerts, max_memory_mb), vector cache budget, crawl/WP client factory, WordPress defaults,
  AI env fallback (`[llm]`) and the embed chain (`EmbedChain::reconfigure`) read it on each use.
- Default `hybrid_gpu_share` is **0.5**, not 0.7 (benchmark in docs/testing/performance.md: at 0.7 the GPU, which gets the
  longest texts, is the bottleneck). Default `default_min_links_per_post` is **3** (the engine default, so an untouched
  `[wordpress]` section changes nothing).
- GET extras: `resources.cpu_threads_pool`, `resources.memory_pressure`; `compute.remote_key`/`remote_key2` and
  `backup.passphrase` are reported as `"***"`/`""`; `monitor.maintenance_cron`, `monitor.event_log_retain_days`,
  `monitor.log_reads` are readable/writable. PUT answers the full GET document plus `changed: [keys]` and, when a process
  environment variable overrides a key, `warnings`.
- PUT secrets: `"***"` = unchanged, `""` = clear (the `secrets.env` line is removed). `compute.remote_key` →
  `OPENROUTER_API_KEY`, `remote_key2` → `OPENROUTER_API_KEY_T2`, `backup.passphrase` → the variable named by
  `backup.passphrase_env` (min 8 chars).
- Keys that have a `secrets.env` override line (`EMBED_CHAIN`, `EMBED_REMOTE_MODEL`, `DARIO_URL`, `DARIO_MODEL_*`,
  `CRAWL_ALLOW_PRIVATE_HOSTS`, `SILOFORGE_CPU_THREADS`, `SILOFORGE_BINDS`) are written to that line instead of the TOML,
  so the change survives a restart. `wordpress.user_agent` is stored as `[crawl] user_agent` (one UA for crawl + WP).
  `server.allow_registration` is `[auth] allow_registration`; `server.mcp_http_enabled` is the MCP policy's `http_enabled`.
- `restart_required` = keys whose live value differs from the boot value among `server.binds`, `server.cors_origins`,
  `resources.cpu_threads`. `cpu_threads` is also applied live as a "threads in use" limit (work is routed to a smaller
  rayon pool); raising it above the boot pool size needs the restart.
- `POST /system/restart` → 202 `{restarting:true}`; 501 when the process has no restart hook. The serve loop shuts down
  gracefully, releases the instance lock and ports, then: under the keepalive task (parent is `conhost --headless`, or
  `SILOFORGE_RESTART_MODE=task`, task name `SILOFORGE_RESTART_TASK`) a detached `cmd /c ping -n 3 127.0.0.1 >nul &
  schtasks /run /tn siloforge-keepalive` — `ping` instead of `timeout /t 2` because `timeout` aborts at once without console
  input; otherwise (`exec`) the same exe is started with the same args; `none` = just exit.
- `max_memory_mb`: monitor compares process RSS each sample (over when RSS > cap, clear below 90 %); while over, the
  vector cache budget is quartered and idle caches dropped, heavy jobs are deferred, one `system.alert` per 30 min.

**§2 Tokens** — PATCH also accepts `tool_policy: {allow: [...]|null} | null` (stored in the MCP policy `per_token`); rows in
GET /tokens and the PATCH answer carry `tool_policy`. Lowering a token's scopes caps its descendants (a descendant with no
scope left is revoked); the answer has `descendants_capped`. An API token may PATCH only when it has `*`/`admin` (same as
create).

**§3 MCP** — Usage is recorded by sf-mcp for both transports with `POST /api/v2/mcp/usage {tool, ok, duration_ms, error}`
(204, any authenticated user/token, also read-only ones); aggregated per tool and hour in `kv` (`mcp_usage:<hour>:<tool>`,
48 h kept). `GET /mcp/stats` adds `avg_ms`, `category`. `GET /mcp/policy/effective` →
`{http_enabled, scope, allowed, tools, token_id, restricted}`. `GET /mcp/policy` tool entries add `default_enabled`,
`default_min_scope`; PUT stores only overrides of the catalogue defaults; `tools`/`per_token` given in a PUT replace the
stored maps. `GET /api/v2/mcp` tool entries carry `min_scope`, `enabled`, `default_enabled`, `category`, and the top level
`http_enabled`. sf-mcp fails open (all default-enabled tools) when the policy endpoint is missing/unreachable and keeps
the last known policy on transient errors.

**§5 Downloads** — the file response also has `x-sha256`; computed hashes are cached in memory by (name, size, mtime).

**§8 MCP tools** — 118 tools (28 kept + 90). `siloforge_bulk_inject` / `siloforge_bulk_undo` keep their v1 semantics and do
**not** require `confirm` (Hermes workflows depend on them); every new destructive tool requires `confirm: true`.
Skipped for lack of a route: site delete, edge get, edge score breakdown, single post get. `siloforge_api_request` refuses
auth routes, plugin sync routes, `POST /api/v2/tokens`, downloads, traversal/encoded separators/absolute URLs, needs
`confirm` for non-GET, is admin scope and disabled by default. Token plaintexts and rotated site keys are stripped from
tool output.

**§9 Logs** — `GET /logs` also takes `after_id` (rows with id > after_id, ascending, answer has `next_after_id`, for live
tail); `source`/`status` accept comma lists; `since`/`until` accept RFC 3339 or relative `15m`/`24h`/`7d`.
`/logs/stats` → `{by_source, by_status, total}`. Rows: `{id, ts, source, actor, action, target, site_id, status,
http_status, duration_ms, detail, user_id}`. Request status: `denied` for 401/403, `error` for any other status >= 400.
Job rows: action `job <kind> queued|started|done|failed|retry|cancelled`, `target` = job id and `detail.job_id`.
Non-admin users, and admin API tokens without `*`/`admin`, see only rows with their `user_id` (job/notify rows carry the
site owner). Anonymous requests count as `ui` when the browser sends `Sec-Fetch-*` headers, else `api`. Writer: bounded
mpsc, batches every 1 s or 500 rows, never blocks a request (overflow is counted and dropped). System events: start,
stop (with `restarting`), restart requested, settings changed; backup results are logged as their job rows and
notifications.
